# Write release notes

Work from the ticket and the change. If you weren't given them, ask which ticket it is, and read the change with `git diff`. Write the release-notes section for this change, for customers.

- A short heading per change, in sentence case, saying what customers get.
- One or two short paragraphs under each: what is different, where to find it, and what to do if they want the old behaviour.
- Exact numbers and menu paths, as in the ticket.
- Follow the voice exactly. No savings figures.

Markdown. No introduction or sign-off.
